# ADR 0003: GitHub ActionsによるCI

ステータス: 採択→adrジョブはADR 0005

## 文脈

ビルドの破損（[ADR 0001](0001-build-on-stable-rust.md)の `box_syntax` のような問題）を、変更した時点で検出する仕組みがない。
また、ADRの変更不可（[ADR 0002](0002-adr-immutability-hooks.md)）は、ローカルhookを有効にしていない環境では検査されない。

## 実装すること

`.github/workflows/ci.yml` を追加する。

- トリガー: `main` へのpushと、すべてのpull request。
- `check` ジョブ（`ubuntu-latest` と `macos-latest` のマトリクス）
  - `rustup` でstableツールチェインと `rustfmt`、`clippy` を入れる。
  - `cargo fmt --check`
  - `cargo clippy --all-targets --locked -- -D warnings`
  - `cargo test --locked`
- `adr` ジョブ（`ubuntu-latest`）
  - pull requestではベースブランチと `HEAD` を比較元、比較先として `scripts/check-adr-immutable.sh` を実行する。
  - pushではpush前のコミット（`github.event.before`）と `HEAD` を比較する。push前のコミットが存在しない場合（ブランチ作成時）はスクリプト側で成功とする。

## 実装しないこと

- リリースビルドや成果物の配布は行わない。`v` タグによるリリースは別のADRで扱う。
- ビルドキャッシュは導入しない。依存が少なく、ビルド時間が短いため。
- Windowsでのテストは行わない。`MAIN_SEPARATOR` を前提にしたテストが `/` を使っているため、別途対応が必要になる。
- サードパーティのアクション（`dtolnay/rust-toolchain` など）は使わない。ランナーにプリインストールされている `rustup` で足りるため。

## テスト設計

- ブランチをpushしてpull requestを作り、全ジョブが成功することを確認する。
- コミット済みADRの本文を書き換えたコミットで `adr` ジョブが失敗することを、ローカルで `scripts/check-adr-immutable.sh` を同じ引数で実行して確認する。

## トレードオフ

- stableの更新に追従するため、新しいclippyのlintでCIが突然失敗することがある。その場合は都度コードを修正する。
- `actions/checkout` のみ外部のアクションに依存する。
